# Repository instructions

## Scope

- This repository owns the `pptdif` CLI, which compares two PowerPoint
  presentations (slides, text, shapes, formatting) with content-aligned
  slides, and the `pptdif` agent skill that drives it.
- `crates/pptdif` owns every presentation rule and has no process I/O.
  `crates/pptdif-cli` adapts it to the process contract.
  `crates/pptdif-fixtures` writes synthetic test decks and is used only by
  tests.
- `skills/` holds the published skill catalog: `skills/pptdif/SKILL.md`,
  `agents/openai.yaml`, and directly linked resources.
- `.agents/skills/` and `.claude/skills/` are generated by `sjskills` from
  `sjskills.toml`; never edit those copies.

## Read first

- `PLAN.md` for decisions, the milestone in progress, and the next action.
- `TODO.md` for open items and facts still to verify.
- `ARCHITECTURE.md` for boundaries, invariants, and the JSON process
  contract.
- `README.md` for commands and building.

## Confidentiality

- `fixtures/private/` holds real decks and is git-ignored. Their contents,
  file names, slide titles, sizes, and derived values must never be
  committed, quoted in docs, tests, or commit messages, or uploaded.
- Public tests use only synthetic decks built by `crates/pptdif-fixtures`
  or PowerPoint-saved files with invented content.

## Working rules

- The process contract is a compatibility surface: one newline-terminated
  stdout document per invocation, stable `error.code` values, and exit codes
  0/1/2. Add fields without removing old ones; a breaking change needs a new
  `metadata.contract`. Keep its shape aligned with `../xldif` and
  `../dsdai`.
- Modules copied from xldif (`package.rs`, `xml.rs`, `align.rs`,
  `error.rs`) name their origin. When fixing one, check whether xldif needs
  the same fix.
- A file-format fact is verified only after it has been observed in a
  PowerPoint-saved deck. Until then, mark it as unverified in `TODO.md` and
  the code.
- A behavior change needs a test: CLI behavior in
  `crates/pptdif-cli/tests/cli.rs`, library behavior next to the code.

## Release

- `.github/workflows/release.yml` builds and publishes the Windows x64
  archive when a `v*` tag matching the workspace version in `Cargo.toml` is
  pushed. The workspace version is the version authority. The workflow runs
  only for tags pushed by `sjunepark` (the maintainer); change its `if:` to
  add others. Never push tags or create releases as part of ordinary
  implementation work.
- To release: set the version in `Cargo.toml`, run `cargo update
  --workspace` so `Cargo.lock` carries it (the workflow builds with
  `--locked`), commit both, then push the `v*` tag for that commit.

## Validation

- `python scripts/check.py` runs skill package checks, `cargo fmt`, `clippy`
  (pedantic, warnings denied), `test`, a CLI smoke run, and reader parity
  against python-pptx on the public fixtures and, when `fixtures/private/`
  exists, the private corpus (counts only).
- Run it after any change to code, the skill, or fixtures.
